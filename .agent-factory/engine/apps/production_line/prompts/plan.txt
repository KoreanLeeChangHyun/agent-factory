# JSON key rule
- schema_version: 2 (T-504 — JSON format + plan/ directory)
- work_request: WR-NNN
- command: implement | research | review | test
- mode: single | multi
- phases: A non-empty list. Each item key:
  - id: English + numbers (P1, P2, ...), unique
  - title: Short one line (Korean OK)
  - deps: ID list. Allow empty list. Self-referencing/non-existent ID is prohibited.
  - deliverable: `work/<id>/W1.md` (nested recommended). flat `work/<id>.md` is also backward compat.
  - spawn_mode: in_place (default) | subprocess (tasks that require isolation)
  - workers: 1 (default). 2+ is a star track.
  - acceptance_criteria: list[str]. command=implement definite obligation (1+ items).

# Writing rules
- in_place is default. Subprocess only when isolation is necessary (DB write / external network / large capacity context).
- Dependency decomposition into topological order. No circular dependence.
- The phase id / deps of plan.json and plan.md must match (driver `parse_plan_json`
  schema validation + cycle detection).

# Force TDD (command=implement, T-503)
- The acceptance_criteria of each phase is in a deterministically verifiable form:
  - "pytest <test_file> passed"
  - "<file path> exists"
  - "<command> exit code 0"
  - "<import path> No ImportError"
- In the WORK stage, each acceptance_criteria item is processed as Red→Green→Refactor.
- Driver `_verify_code.py` calls pytest -q + ​​ruff check + mypy followed by → R-CODE-1/2 evaluation.

Acceptance_criteria is not applied to research/review orders. However, it can be specified as an empty list `[]`.

# output tool
Write 2 calls (plan/plan.json + plan/plan.md). Minimize use of other tools.

## 3. 본문 기록

### 3.1. context-and-scope

- Context and Scope
- workspace-body, workspace-panel, empty-state의 전체 폭 배치
- 5개 workspace-tab의 동일 너비 전체 폭 배치
- VS Code semantic theme token 기반 탭, 헤더, 본문 표면 정렬
- 관련 단위·E2E·Human 화면 검증
- 탭 이름, 순서와 보이는 문구 변경
- DOM 구조, 이벤트, 키보드 탐색과 상태 보존 변경
- 각 탭의 실제 기능 구현
- Webview 메시지 및 보안 경계 변경

### 3.2. decisions-and-open-items

- Decisions and Open Items
- 기존의 제한된 콘텐츠 폭과 가운데 카드 배치를 전체 폭 본문으로 대체하고, 5개 탭을 균등 분할하며, 색상은 VS Code semantic theme token에 맞춘다.
- Human이 완료 화면을 검토한 뒤 전체 폭 본문, 균등 탭과 VS Code 색상 정렬을 명시적으로 요청하고 새 후속 lifecycle을 선택했다.
- accepted
- resolved
- 최외곽 Webview gutter만 제거하고 selected-header와 empty-state의 내부 읽기 여백은 유지한다.
- Human이 첨부 화면 검토 후 선택지 A를 명시적으로 선택했다.

### 3.3. evidence-and-findings

- Evidence and Findings
- workspace-panel은 clamp(20px, 3vw, 40px) 패딩을 사용한다.
- empty-state는 width min(100%, 720px)와 margin-inline auto를 사용한다.
- workspace-tab은 flex 0 0 auto이고 tablist에는 좌우 반응형 패딩과 2px gap이 있다.
- 탭, 헤더, 카드가 VS Code theme token을 사용하지만 선택 헤더와 카드에는 editorWidget 표면이 적용된다.
- 기존 Specification은 제한된 콘텐츠 폭을 요구한다.
- 완료 Work Unit은 done 상태이며 관리자가 rework-start를 거부했다.
- Human의 전체 폭 요청은 기존 제한 폭 요구사항과 Specification을 대체해야 한다.
- 새 후속 Intake와 Work Unit이 필요하다.
- 어느 범위까지 좌우 여백을 제거할지 결정
- 최외곽 gutter를 제거하면서 헤더와 본문 텍스트의 가독성 여백을 보존한다.
- A
- A: 최외곽 공백만 제거하고 내부 읽기 여백 유지
- B: 모든 좌우 여백 제거
- C: 현재 상태 유지
- answered

### 3.4. request-and-goal

- Request and Goal
- 본문 panel과 empty-state가 최대 폭 제한 및 바깥 좌우 여백 없이 가용 폭을 사용한다.
- 5개 탭이 동일한 너비로 tablist 전체 폭을 채운다.
- 헤더, 탭과 본문 표면은 VS Code semantic theme token을 사용한다.
- 기존 탭 문구, DOM, 키보드 탐색과 상태 보존이 유지된다.

### 3.5. requirements-and-constraints

- Requirements and Constraints
- workspace-body, workspace-panel과 empty-state는 에디터의 가용 가로 폭을 사용한다.
- workspace-panel은 바깥 좌우 padding을 두지 않고 empty-state는 720px 최대 폭과 자동 가운데 정렬을 사용하지 않는다.
- 5개 workspace-tab은 동일 너비로 tablist 전체 폭을 채운다.
- 탭, 선택 헤더와 본문 표면은 역할에 맞는 VS Code semantic theme token을 사용한다.

## 2. 결정 목록과 질문 수 수정

- 최초 목록은 클릭 동작과 적용 범위의 2건이며, 당시 질문 표기는 1/2와 2/2였습니다.
- Main은 이후 주입된 워크플로가 요구하는 Specification 정체성·목적지와 완료 신호가 미해결임을 식별했습니다.
- 누락된 문서 결정을 질문 3으로 추가하여 총 질문 수를 **2개에서 3개로 수정**합니다. 새로운 제품 요구나 답변 정정 때문이 아니라, 초기 결정 목록에서 문서 결정이 누락되었기 때문입니다.
- 완료 신호도 별도로 미해결 상태로 보존합니다. 목적지 응답만으로 완료를 추정하지 않습니다.

## 6. 현재 요약과 미해결 사항

- 질문 1은 권고 1과 달리 Human이 2를 선택하여 클릭 즉시 전송을 수락하셨습니다.
- 질문 2는 권고와 Human 선택이 모두 3이며, Agent가 지정한 클릭 가능 질문에만 적용하는 범위를 수락하셨습니다.
- 두 제품 결정에 정정은 없습니다. 세부 구현 방식은 이 기록에서 결정하지 않았습니다.
- 질문 3의 문서 정체성·목적지와 워크플로 완료 신호는 미해결이며, Specification 승격은 보류 상태입니다.
- S1~S3의 주입된 워크플로는 정체성과 의미가 해결된 뒤 확립된 완료 신호에 따른 승격을 이미 요청하고 있습니다. 일반적인 실행 승인이나 이미 허용된 승격의 재승인을 추가로 요구하는 사안이 아닙니다. Human의 완료 확인은 신호가 될 수 있으나, 현재 그런 신호를 기록할 근거는 없습니다.
- 주입된 워크플로에는 Client Specification의 한국어 `docs/specification/<category>-<name>/index.html`과 영어 `.codex/skills/<category>-<name>/SKILL.md` 쌍을 요구하는 내용이 있습니다. 이번에 읽은 Convention은 Human 언어의 단일 `docs/specification/<category>[-<domain>]-<name>/SKILL.md`를 정본으로 규정합니다. 이 계약 차이를 여기서 해소하거나 기존 문서를 덮어쓰지 않습니다. 기존 `design-main-chat` 본문은 이번 작업에서 조사하지 않았습니다.
- 현재 승인된 작업은 이 Processed 기록의 신규 작성까지입니다. 문서 작성이나 Work 완료는 인터뷰 전체 완료, 구현 승인 또는 Specification 승격을 뜻하지 않습니다.

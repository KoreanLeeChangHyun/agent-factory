Agent Factory Workspace

진입 계약

사람용 프로젝트 관제탑에 이 Skill을 사용합니다. 세 주요 영역은 작업 표시줄, 기본 사이드바, 작업 영역(Activity Bar, Primary Sidebar, Workspace area)입니다. 작업 표시줄에는 일정, 에이전트, 문서, 외부연동, 로그, 테스트의 정확히 여섯 Activity만 이 순서로 둡니다. 다른 최상위 Activity나 별칭을 추가하지 않습니다.

Workspace는 투영·제어 화면입니다. Agent, Document, Gather, Tool, provider, credential, catalog 상태를 소유하거나 실행하지 않습니다. 소유자가 제공한 사실과 control만 표시하고, 미결정 영역은 그대로 드러내며, 설정이나 로컬 artifact로 live 상태를 추론하거나 sample data를 만들지 않습니다.

작업 선택

작업 전에 관련 참조를 끝까지 읽습니다.

  • references/activities.md는 여섯 Activity의 정보구조, 외부연동 분류, 문서 sidebar, discovery 상태와 미결정 Activity 범위를 소유합니다.
  • references/interface.md는 browser shell, 접근성·시각 동작, 문서 table·explorer, recursive Specification tab·split, packaged/local 게시, launcher·server 동작, 저장·권한 경계를 소유합니다.

정보구조와 interface 동작을 함께 바꾸면 두 참조를 모두 읽습니다. 상세 계약을 이 문서에 다시 쓰지 않습니다.

게시와 저장

선택된 Agent Factory MCP 애플리케이션이 FastAPI host, MCP transport, tenant API, canonical browser asset, 배포 adapter와 runtime test를 소유합니다. Plugin은 Workspace Skill 계약만 유지하며 runtime이나 browser asset을 배포하지 않습니다.

<agent-factory-mcp>/app/               FastAPI, MCP, domain runtime
<agent-factory-mcp>/static/workspace/  canonical browser asset
<agent-factory-mcp>/tests/             runtime contract test

소비자 프로젝트에는 .agent-factory/workspace/, 복사된 asset, launcher, port file 또는 Workspace projection을 만들지 않습니다. PostgreSQL과 object storage가 tenant Workspace data의 권위 저장소입니다. Client의 비권위 설치·연결 상태는 project 밖 ~/.agent-factory/에 둘 수 있습니다. Legacy project-local Document는 원본을 삭제하기 전에 inventory, backup, MCP import를 거쳐야 합니다.

완료 조건

Workspace 변경은 다음 조건을 모두 만족해야 완료됩니다.

  • 여섯 Activity의 순서와 결정·미결정 경계가 references/activities.md와 일치합니다.
  • 영향받은 browser, navigation, 접근성, 보안, 게시 규칙이 references/interface.md와 일치합니다.
  • 선택된 MCP runtime의 집중 test가 통과합니다.
  • 투영 대상 domain 상태를 만들거나 변경하거나 넘겨받지 않았습니다.
  • Skill과 Human Specification이 함께 동기화됩니다.

Workspace Activity

최상위 계약

Workspace에는 일정, 에이전트, 문서, 외부연동, 로그, 테스트의 정확히 여섯 Activity가 이 순서로 있습니다. 정확한 한국어 label은 Activity Bar의 장식용 SVG 아래에 표시합니다. 별칭이나 다른 Activity를 추가하지 않으며 순서가 domain 사이의 소유권이나 workflow를 뜻하지 않습니다.

외부연동은 Primary Sidebar와 Workspace view를 가진 일반 Activity이며 하단 utility가 아닙니다. Sidebar에는 웹·리서치, 문서·파일, 메일·메시지, 일정·회의, 지식·업무관리, 개발·운영, 데이터·비즈니스의 비대화형 업무 목적 group 일곱 개를 이 순서로 둡니다.

Provider, account, integration method, status, permission scope, 마지막 synchronization 시각은 category가 아닌 item attribute입니다. Category는 connection, source selection, nested navigation, category별 control을 뜻하지 않습니다. Workspace view는 외부연동 상태 연결 대기로 시작하고 owner-backed integration fact만 표시할 수 있습니다. 상세 rendering과 future loader 계약은 references/interface.md가 소유합니다.

문서 Sidebar

문서 Primary Sidebar에는 서로 독립적으로 접을 수 있는 원본 문서, 가공 문서, 명세 문서 group이 이 순서로 있습니다. 이는 정확한 사람용 label이며 logical type, identifier, metadata, path를 바꾸지 않습니다.

원본 문서

원본 문서에는 개요와 문서검색이 있습니다. 검색은 compact Tabulator 6.5.2 view에서 global search, column filter, sort, Human resize·reorder와 문서 분류, 출처, 태그, 문서 이름, 확장자, 수정 일자의 정확한 column 순서를 제공합니다.

문서 이름 cell만 source Original로 연결합니다. Provider cell은 보이는 text와 장식용 inline SVG를 유지합니다. 이는 read-only metadata/link projection이며 Workspace는 Original 본문을 복사·변경하거나 Gather synchronization을 소유하지 않습니다.

가공 문서와 명세 문서

각 group에는 개요 바로 뒤에 보이는 탐색기 parent row가 있고 실제 Document 목록이나 정직한 상태를 그 아래에 둡니다. Processed discovery는 local direct package를 나열하고 안전한 same-origin index.html이 있으면 열며, 없으면 missing-entry를 표시합니다.

Specification discovery는 상호 Human/AI binding metadata를 비교해 paired, misaligned, missing-human을 보고합니다. paired entry만 이동할 수 있습니다. 선택하면 read-only editor group에서 Human browser document를 열거나 활성화합니다. Explorer는 actual tree이며 click을 non-drag fallback으로 지원합니다.

Row geometry, short title, same-origin allowlist, keyboard model, tab·close, drag-and-drop, recursive split, empty state, iframe 처리와 cleanup은 references/interface.md만 소유합니다.

결정·미결정 범위

결정된 범위는 여섯 최상위 label·순서, 외부연동 일곱 category, 위 문서 Sidebar와 read-only discovery 형태뿐입니다.

일정·에이전트·로그·테스트 Sidebar와 세부 capability, overview content, live Original source/query, synchronization trigger·status, metadata mutation authority·persistence, 외부연동 category navigation·child source·owner-backed projection 밖의 lifecycle control은 Human 소유이며 미결정입니다. awaiting definition 또는 connection 상태로 표시하고 hierarchy, record, metric, control, account, connection health, capability를 발명하지 않습니다.

권한 경계

Workspace는 owner-backed state를 표시하고 승인된 control을 연결하지만 canonical owner가 되지 않습니다. Agent는 execution·catalog, Document는 Document, Gather는 external synchronization, Tool은 logical external tool/connector lifecycle을 소유하며 각 provider가 권위를 유지합니다. 기존 local discovery directory나 utility는 Activity를 만들거나 그 아래 nesting을 승인하지 않습니다.

Workspace 인터페이스

Human 관제탑

  • Workspace는 개발자에게 익숙한 VS Code 형태 shell을 사용하며 기본 공간 관계는 작업 표시줄 → 기본 사이드바 → 작업 영역입니다.
  • 이 이름은 각각 Activity Bar, Primary Sidebar, Workspace에 대응합니다.
  • 나중에 투영할 수 있는 상태의 canonical store나 executor가 되지 않으면서 Human navigation과 control을 위해 project state를 표시합니다.
  • 공통 layout, interaction, visual token은 .agent-factory/workspace/common/에 유지합니다.
  • Activity Bar에는 정확히 일정, 에이전트, 문서, 외부연동, 로그, 테스트의 여섯 top-level Activity item만 이 순서와 한국어 label로 있습니다.
  • 각 label은 Activity Bar에서 장식용 inline SVG icon 아래에 보이는 text로 render하며, 지원하는 좁은 viewport에서도 icon-only navigation으로 접지 않고 label을 유지합니다.
  • 다른 top-level Activity item은 허용하지 않습니다.
  • 특히 별도 Explorer/File Explorer, Planning/Specification, Project Skills, overview/dashboard, Roadmap 또는 alias button을 추가하지 않습니다.
  • 외부연동을 data-activity="external-integrations"를 사용하는 네 번째 일반 Activity로 render하며 하단 utility나 overlay로 만들지 않습니다.
  • 다른 Activity와 같은 interaction으로 대응 Primary Sidebar와 Workspace view를 선택합니다.
  • Primary Sidebar는 웹·리서치, 문서·파일, 메일·메시지, 일정·회의, 지식·업무관리, 개발·운영, 데이터·비즈니스의 정확히 일곱 대분류 그룹 행을 순서대로 가진 semantic list입니다.
  • 각 label은 visible text이고 실제 interaction이 결정되기 전에는 button, link, selected state, disclosure, 만들어낸 count를 두지 않습니다.
  • 이 목록은 180–520 px sidebar 범위에서 읽을 수 있어야 합니다.
  • 문서 기본 사이드바의 compact group-heading 행과 같은 높이, typography, label inset, background, divider rhythm을 사용하고 중복 내부 제목과 disclosure-icon slot은 두지 않습니다.
  • 업무 목적이 분류 축이며 provider/account/method/status/permission scope/last synchronization은 item attribute입니다.
  • Workspace view는 sample integration 없이 정직한 외부연동 상태 연결 대기 상태로 시작합니다.
  • Activity view는 read-only projection boundary입니다.
  • 미래 owner-backed loader를 위해 window.agentFactoryWorkspace.externalIntegrations.replaceItems(items)를 노출합니다.
  • 모든 item은 비어 있지 않은 stable integrationIdentity를 가진 object이며 선택적 provider, account, method, status 값은 plain text로 render하고 duplicate identity는 fail closed합니다.
  • 빈 adapter result는 view를 waiting state로 되돌립니다. authoritative provider와 lifecycle route가 구현되기 전에는 개인 계정을 hardcode하거나 installed/connected/healthy state를 추론하거나 secret material을 노출하거나 connection/disconnection control을 추가하지 않습니다.
  • 외부연동은 plugin, connector, MCP server, 직접 OAuth/API integration, local mount·synchronization, service account, external document URL, manual import를 포괄하는 Human용 상위 개념이며 connector는 한 method일 뿐입니다.
  • Workspace는 projection과 interaction만 소유하고 Tool과 실제 host/plugin/MCP server/provider는 lifecycle authority를 유지합니다.
  • Activity Bar item 하나는 대응하는 Primary Sidebar view 하나와 main Workspace view 하나를 소유합니다.
  • Document sidebar에는 눈에 띄고 독립적으로 접히는 explorer 형태 group이 원본 문서, 가공 문서, 명세 문서 순서로 있습니다.
  • Original은 개요와 문서검색을 제공하고, search item은 top tab bar 없는 compact semantic table view를 선택합니다.
  • 정렬, column resize/reorder, global text search, 모든 column filter를 위해 local vendored Tabulator 6.5.2 배포본을 정확히 고정하여 사용합니다.
  • 보이는 순서와 label은 정확히 문서 분류, 출처, 태그, 문서 이름, 확장자, 수정 일자입니다.
  • Tabulator fitColumns layout은 명시적이고 내용에 적절한 widthGrow weight로 일반 desktop table 폭을 여섯 column에 배분합니다. column별 minimum width와 table minimum width는 실제 좁은 viewport에서 가로 overflow를 보존합니다.
  • 수동 column resize와 move를 계속 허용합니다.
  • 문서 이름 header는 plain text이고, 값이 있는 각 이름 cell이 source link입니다.
  • 출처는 장식용 inline SVG와 보이는 provider text를 함께 표시해 color만으로 구분하지 않습니다.
  • Processed와 Specification은 각각 개요를 제공하고 그 바로 아래에 보이는 탐색기 부모 행을 둡니다.
  • 실제 Document 목록 또는 정직한 loading, empty, unresolved, error state는 탐색기 행의 sibling이 아니라 그 탐색기 안에 중첩합니다.
  • 두 영역은 시각적·의미적으로 일관됩니다.
  • 한국어 UI label은 정확히 명세 문서이며 semantic type, identifier, metadata, path는 계속 Specification과 specification입니다.
  • 개요와 탐색기를 동일한 explorer-row geometry와 interaction 문법으로 render합니다. fixed row height, 줄어들지 않는 동일 icon 크기, 하나의 label baseline, 정렬된 icon/label 축, 일관된 hover/visible-focus background와 alignment를 사용합니다.
  • 탐색기에는 leading disclosure-arrow slot을 주되 folder icon과 label은 overview document icon/label 축에 맞춥니다. compact한 VS Code형 child 정렬을 사용합니다.
  • 펼쳐진 각 child Document의 14 px SVG icon을 현재 row 문법에서 22 px logical inset인 탐색기 folder-icon axis에 둡니다.
  • child title은 14 px icon과 4 px gap 뒤에서 시작해 탐색기 parent-label axis에 맞춥니다.
  • parent disclosure arrow만으로 시각적인 parent/child 구분을 제공하며 다른 icon-plus-gap offset을 추가하지 않습니다.
  • nested list의 margin과 inline padding을 0으로 reset하고 marker를 제거하여 user-agent list padding이 child inset에 더해지지 않게 합니다.
  • Document row는 default 252 px와 지원하는 180–520 px resize 범위에서 한 줄이어야 합니다.
  • icon은 줄어들지 않고 text 영역만 줄어들어 ellipsis를 사용하며 horizontal scroll을 만들지 않습니다.
  • native HTML title text에 전체 Document 이름을 보존합니다.
  • selected, hover, focus 처리는 같은 row box에 적용합니다.
  • 정직한 loading/empty/error/unresolved message는 별도의 읽기 좋은 supporting state로만 render하며 wrapping할 수 있지만 Document row와 겹치지 않습니다.
  • Processed 영역은 /api/processed-documents를 load하고 모든 immediate local Processed package를 Specification과 같은 child-row geometry로 표시합니다.
  • 안전한 index.html은 exact same-origin /processed/<id>/index.html에서만 열고 browser entry가 없는 package는 unavailable missing-entry row로 계속 표시합니다. legacy Markdown을 숨기거나 active format으로 취급하지 않습니다.
  • Processed와 Specification row는 짧고 간단한 visible title을 사용하고 전체 title은 native HTML title text로 보존하며 visible label은 한 줄 ellipsis를 사용합니다.
  • Specification 영역은 /api/specifications를 load합니다.
  • 이 endpoint는 reciprocal binding metadata로 resolve된 project의 Human HTML entry point와 AI Skill counterpart를 발견합니다.
  • 각 paired Human document title을 same-origin link로 render합니다.
  • 선택하면 기존 /planning/<id>/index.html을 복사하거나 편집하지 않고 Workspace document area에서 load합니다. misaligned와 missing-human은 non-navigable error state로 표시합니다.
  • 빈 결과는 연결된 명세 문서가 없습니다., request 실패는 명세 문서를 불러오지 못했습니다.로 표시합니다.
  • discovered entry ID와 lowercase hyphen-case path ID가 같은 exact same-origin /planning/<id>/index.html만 허용합니다.
  • credential, query string, fragment, broader /planning/ prefix, malformed ID, ID/path mismatch를 거부합니다.
  • Specification explorer는 recursive VS Code 형태 editor-group viewer의 read-only source입니다.
  • discovered entry는 actual tree item이고 각 split leaf는 semantic tabstrip과 연결된 panel을 가진 editor group입니다.
  • paired item click은 DnD 불가 환경의 baseline path로 active group에 tab을 열며, 같은 Document가 그 group에 이미 있으면 중복하지 않고 활성화합니다.
  • tab click은 연결된 panel/iframe으로 전환합니다.
  • 긴 title은 ellipsis를 사용하되 native title로 전체 이름을 제공합니다. tabstrip과 panel은 WAI-ARIA tab 관계를 사용하고 ArrowLeft/ArrowRight/Home/End 및 Enter/Space keyboard 동작을 제공합니다. active group은 그 group의 active tab과 별도로 추적하며 explorer selection은 active tab을 따릅니다.
  • 첫 Document를 열기 전에는 empty workspace guidance가 유지됩니다.
  • empty editor나 group center drop은 target group에서 tab을 열거나 활성화하고, left/right edge는 horizontal split, top/bottom edge는 첫 tab을 가진 새 vertical split group을 만듭니다.
  • existing split 안의 group도 center/edge drop target이어서 재귀적으로 split됩니다.
  • internal drag 동안 iframe pointer hit testing은 owning group에 양보하여 dragover/drop이 embedded document에 삼켜지지 않게 합니다.
  • 다른 Document view에서 dragover로 전환해도 empty editor가 first drop을 받아야 합니다. group이 sole editor group일 때만 마지막 tab 이후 남을 수 있습니다.
  • 그 sole zero-tab group ID를 flat한 full split leaf로 유지하고 tabstrip 아래 content area 전체에 guidance를 가운데 배치하며 fixed/max-size, border, color가 있는 empty-state card를 render하지 않습니다.
  • zero-tab group은 다른 survivor 옆에 두지 않습니다.
  • center와 edge drop indicator는 실제 internal Specification drag가 active일 때만 render합니다.
  • center indicator는 inset floating card가 아니라 tabstrip 아래 full-content target이고 네 edge indicator는 directional split region을 유지합니다.
  • 성공하거나 invalid인 drop, dragend, Escape나 다른 cancel, Activity 또는 Document-view change, 마지막 tab close는 dragged identity, body drag class, layout/group drop marker, iframe hit-testing override를 모두 지웁니다.
  • normal no-drag group에는 drop indicator가 남아서는 안 되며 active-group focus outline은 empty group의 permanent blue ring이 아닌 별도 semantic focus state입니다.
  • pointer/focus interaction은 group을 active로 표시하고 이후 explorer click은 그 group에서 tab을 열거나 활성화합니다.
  • global 명세 문서 편집기 header는 표시하지 않고 group tabstrip chrome만 사용합니다.
  • 열린 tab마다 tab activation button 안이 아니라 그 옆에 실제 close button을 둡니다.
  • 장식용 inline SVG X에는 aria-hidden=true와 focusable=false를 적용하고 button에는 <문서 전체 이름> 닫기 accessible name과 native title을 둡니다.
  • 좁은 tab에서 title ellipsis와 고정 close hit target을 유지하며 hover, focus, active tab에서 control을 명확히 보이고 keyboard focus도 보이게 합니다. close-button focus는 group activation route에 들어가지 않고 close-button click은 tab activation이나 split/drop으로 전파되지 않습니다.
  • 일반 tab activation과 group focus/click은 계속 group을 활성화합니다.
  • inactive tab을 닫으면 대상 group의 현재 active tab/panel을 유지합니다. locally active tab을 닫으면 바로 오른쪽 이웃을 활성화하고 오른쪽이 없을 때 왼쪽을 활성화합니다.
  • 대상 group이 전역 active가 아니면 neighbor activation은 그 group local에만 머물고 직전 전역 active group과 explorer selection을 보존합니다.
  • 어떤 group이 마지막 tab을 닫은 뒤에도 다른 group이 남으면 zero-tab group을 제거하고 direct .specification-split parent를 남은 sibling subtree로 collapse합니다. nested horizontal/vertical tree에 empty 또는 unary split wrapper가 없고 remaining group이 해제된 공간으로 확장될 때까지 split normalize를 반복합니다.
  • 제거 group이 globally active였다면 앞에 있던 group은 sibling subtree의 first leaf를, 뒤에 있던 group은 last leaf를 nearest survivor로 결정하여 active로 만들고 그 local active tab/panel을 explorer selection에 반영하며 가능하면 안전하게 focus합니다.
  • 제거 group이 inactive였다면 이전 global active group과 explorer selection을 보존합니다. collapse 직전/후 drag identity, body state, group/layout drop marker, iframe hit-testing override를 지웁니다.
  • 제거 시 닫힌 group의 tab, panel, iframe, ARIA/group state, listener, drop marker를 폐기합니다.
  • 다른 group이 하나도 없을 때만 마지막 tab을 닫은 현재 group ID를 읽을 수 있는 full-area empty drop target으로 보존하고 explorer selection을 해제합니다.
  • 이후 explorer click이나 center drop은 active surviving group을 사용하거나 sole empty group에 첫 tab을 다시 만듭니다.
  • 같은 Specification이 다른 곳에 열려 있어도 대상 group에만 적용하며 일시적인 viewing state만 제거하고 Specification, Skill, server data를 삭제하거나 수정하지 않습니다.

탭 드래그 앤 드롭

  • 모든 탭은 내부 드래그 대상입니다.
  • 같은 탭 줄에서는 놓은 위치의 앞이나 뒤로 순서를 바꾸며 iframe과 활성 상태를 유지합니다.
  • 다른 그룹의 중앙이나 탭 줄에서는 그 그룹으로 이동합니다.
  • 그룹의 왼쪽·오른쪽·위·아래 가장자리에서는 해당 방향의 새 분할 그룹으로 이동합니다.
  • 대상에 같은 명세가 있으면 기존 탭을 활성화하고 원래 탭을 제거하며 중복하지 않습니다.
  • 그룹 간 이동 뒤에는 마지막 탭 닫기와 같은 빈 그룹 제거, 재귀적 분할 정리, 활성 그룹 선택, 탐색기 동기화, 드래그 정리를 적용합니다.
  • 명시적인 탭 드래그 payload와 move 효과를 사용하여 탐색기 항목의 새로 열기 동작과 구분합니다.
  • 취소되거나 유효하지 않은 탭 드래그는 상태를 바꾸지 않습니다.
  • 이 동작은 일시적인 읽기 상태만 바꾸며 명세를 편집하지 않습니다.
  • pin/preview, dirty state, save/edit, group resize, layout persistence, cross-origin load를 추론하거나 가짜 비활성 control을 표시하지 않습니다.

Packaged asset과 초기화

Workspace browser code에는 두 필수 형태가 있습니다.

  • skills/workspace/assets/browser/{index.html,styles.css,app.js}: 이 project와 다른 project를 위한 reusable distribution 및 installation source.
  • <project-root>/.agent-factory/workspace/common/{index.html,styles.css,app.js}: 정확한 target project에 설치·게시된 copy.
  • 이 셋이 core browser-code file입니다.
  • 두 형태 모두에서 셋을 함께 만들고 유지하며 byte-identical하게 합니다.
  • 필수 packaged companion asset도 같은 two-form publication 계약을 따릅니다.
  • 현재 THIRD_PARTY_NOTICES.txt에는 vendor/tabulator/6.5.2/ 아래 고정 Tabulator file을 포함한 browser code attribution과 license text가 있습니다. initializer는 모든 packaged regular file을 재귀 복사합니다.
  • 모든 vendored file과 notice는 common/ counterpart와 byte-identical해야 하며 notice는 네 번째 browser-code file이 아닙니다.
  • 형태 누락, one-sided change, semantic/byte divergence는 incomplete Workspace change입니다.
  • 이것이 canonical source 두 개를 만드는 것은 아닙니다. packaged asset이 reusable installation source이고 common/은 materialized project copy입니다.

표준 라이브러리만 사용하는 initializer는 skills/workspace/scripts/serve.py입니다. 다음과 같이 정확한 target Git root를 초기화합니다.

python3 <resolved-workspace-skill>/scripts/serve.py \\
  --project-root <target-git-root> init
  • 초기화는 common asset을 <target-git-root>/.agent-factory/workspace/common/에 설치하고, 현재 local adapter의 required directory를 보존하며, Human Specification 및 Document root가 존재하게 하고, assets/workspace.sh를 <target-git-root>/workspace.sh에 한 번 복사합니다.
  • init --force여도 기존 root launcher는 보존합니다.
  • force는 서로 다른 common browser asset에만 적용됩니다.
  • force가 없으면 다른 installed browser file은 preflight conflict입니다.
  • force가 있으면 서로 다른 regular common browser file만 packaged source로 교체합니다.
  • 기존 path containment, symlink, atomic-copy, combined-preflight safeguard는 필수입니다.
  • 초기화는 assets/workspace.gitignore도 없을 때 .agent-factory/workspace/.gitignore로 설치합니다.
  • 기존 regular ignore file에는 정확한 /port.json rule이 이미 있어야 합니다.
  • unsafe/conflicting path는 preflight에서 실패하며 덮어쓰지 않습니다.

일반 Human 사용 명령은 다음과 같습니다.

<project-root>/workspace.sh
# or, from the project root
./workspace.sh --port 9000
  • launcher는 자신의 physical location을 resolve하고 allowlisted local root만 loopback에서 serve하며 /common/을 엽니다. port option이 없으면 유효한 project 저장 assignment를 재사용하거나 OS에 실제 가용 port를 요청하면서 8000을 명시적으로 제외합니다.
  • 성공 bind된 assignment를 exact shape {"version":1,"port":<port>}의 작은 generated local state <project-root>/.agent-factory/workspace/port.json에 원자적으로 게시합니다.
  • 저장 port가 점유되면 다른 non-8000 port를 bind한 뒤 assignment를 교체합니다. --port <port> 또는 -p <port>는 1~65535만 허용하고 8000을 거부하며 성공한 명시 bind를 이후 launch용으로 저장합니다.
  • malformed, out-of-range, symlinked, non-regular, escaping state는 fail closed합니다.
  • state publication은 path containment check, symlink rejection, atomic replacement를 사용합니다.
  • state file은 project별 generated adapter state이고 Git이 ignore하며 packaged browser asset이나 universal backend 계약이 아닙니다.
  • reusable server와 self-contained launcher는 allowlisted root에서 resolve한 모든 성공 static-file response에 Cache-Control: no-store를 붙입니다.
  • mutable /common/ browser shell, local CSS와 JavaScript, vendored 및 companion asset, /planning/ 아래 Human Specification document, 그 밖의 read-only projected static root를 포함합니다.
  • 이 static-file freshness 정책을 JSON API response나 redirect로 확장하지 않습니다.
  • X-Content-Type-Options: nosniff, path containment, symlink rejection, traversal defense를 함께 보존합니다.
  • 실행 중인 Python server는 시작할 때의 handler implementation을 유지하므로 server code를 바꾼 뒤 이미 실행 중인 local Workspace server를 restart합니다.
  • 그러면 다음 browser request가 heuristic cache reuse 없이 현재 file을 가져옵니다.

Storage와 authority 경계

  • local Workspace UI는 projection 및 control surface입니다.
  • 보인다는 사실이 acceptance, health, completion, authority를 뜻하지 않습니다.
  • Agent session, Original/Processed/Specification Document, Project Skill, Human decision은 각 소유 store와 rule을 유지합니다.
  • Agent-owned db.sqlite 카탈로그의 schema와 manager, initialization, rebuild, status, search, publication, recovery는 Agent 소유입니다.
  • Workspace의 serve.py init은 카탈로그를 만들지 않으며 catalog side effect가 없습니다.
  • 현재 catalog/search UI나 source/query binding은 구현되지 않았습니다. Workspace에는 query API나 search executor도 없습니다.
  • 나중에 명시적 Agent-owned interface가 제공한 read-only result를 표시할 수 있지만, 이 가능성은 직접 database access, source/query binding, Activity behavior, Agent/Document/catalog ownership 이전을 승인하지 않습니다.
  • 상세 catalog 계약은 skills/agent/SKILL.md에서만 적용합니다.
  • server-hosted Workspace는 선택된 host나 adapter가 노출하며 local launcher가 필요하지 않습니다. local static-file no-store 계약은 다른 host의 policy를 말없이 선택하지 않습니다.
  • 해당 external host의 backend configuration, identity, synchronization/conflict policy, authentication, availability, caching은 명시적으로 결정될 때까지 미결정입니다.
앞부분의 표와 다이어그램은 보조 안내입니다. 이어지는 원문 파일별 전체 한국어 번역이 skills/workspace/의 AI 표현과 같은 내용을 보존하며, 요약·생략·대체하지 않습니다.

## 3. 본문 기록

### 3.1. context-and-scope

- Context and Scope
- workspace/src/webviewShell.js는 data-kanban-notice role=status 요소를 렌더링한다.
- requestTransition과 kanban.transitionPending 및 kanban.transitionResult 성공 분기가 notice.textContent를 갱신한다.
- 현재 칼럼 표시 선택은 state.closedKanbanColumns와 vscode.getState 및 vscode.setState를 사용한다.
- Kanban 헤더는 공통 제목을 숨기고 칸반 표시 multi-picklist만 노출한다.
- workspace/src/webviewShell.js의 Kanban notice DOM, CSS와 일반 상태 쓰기 제거
- 칸반 칼럼 표시 선택값의 localStorage 저장 및 복원
- Kanban 카드의 타이틀 외 metadata와 모든 액션 제거
- 카드 drag, click, tap, focus와 keyboard Move 상호작용 제거
- workspace/test/unit/webviewShell.test.js 회귀 테스트
- Kanban manager 전이 계약 변경
- 오류 영역 제거
- 검색, 필터 또는 수동 새로 고침 추가
- 다른 탭의 vscode state 계약 변경
- 카드 액션, DnD, keyboard Move 또는 대체 메뉴 재도입
- Human 결정 없는 integration, cleanup, push 또는 배포

### 3.2. decisions-and-open-items

- Decisions and Open Items
- notice 영역 자체를 제거한다.
- 칸반 표시 선택값은 localStorage에 저장해 유지한다.
- 기존 오류 영역은 유지한다.
- 카드는 정적인 타이틀만 표시한다.
- Move UI, DnD, click, tap, focus와 keyboard Move를 포함한 모든 카드 액션을 우선 제거한다.
- 카드 액션 재도입은 DnD affordance, keyboard 동등 경로와 대체 메뉴를 함께 설계하는 후속 Intake로 다룬다.
- 실행 결과의 Human 시각 검토와 별도 integration 결정
- Human은 agent-factory-workspace-kanban-notice-visibility-persistence Work Unit 실행을 요청했다.

### 3.3. evidence-and-findings

- Evidence and Findings
- success notice는 befdf4f Implement Kanban DnD transitions에서 직접 추가되었다.
- 성공 결과는 authoritative snapshot 이후 전송되어 snapshot이 비운 notice를 다시 채우므로 다음 snapshot까지 남는다.
- notice 영역은 일반 상태와 error 영역이 분리되어 있어 notice만 제거해도 error 표시를 유지할 수 있다.
- 기존 canonical 결정은 검색, 필터와 수동 새로 고침을 제거한다.
- 지속 성공 문구는 manager 필수 계약이 아니라 Webview 렌더링 선택이다.
- localStorage의 실제 재개방 동작은 Extension Host 또는 브라우저 기반 실행 검증이 필요하다.
- 스크린샷에는 상태 전이가 적용되지 않았습니다. 문구가 전용 라인에 지속 표시된다.
- webviewShell.js는 data-kanban-notice DOM, CSS와 notice.textContent 쓰기를 포함한다.
- 칼럼 표시 선택은 현재 vscode.getState/setState만 사용하며 localStorage 저장 및 복원이 없다.
- notice 전용 영역 제거와 localStorage 영속화가 Human 요청을 직접 충족한다.
- 실제 Webview 재개방 복원은 Extension Host 시각 검토가 필요하다.
- 모든 액션 제거에 drag and drop도 포함할까요?
- Human의 타이틀만 표시와 모든 액션 제거 요청을 가장 직접적으로 충족하고 추후 액션 재설계를 분리한다.
- C
- A: Move 선택기와 버튼만 제거하고 DnD 유지
- B: 이동 UI와 DnD 제거, 클릭과 포커스 유지
- C: 모든 상호작용 제거, 정적인 타이틀만 표시
- Webviews | Visual Studio Code Extension API
- VS Code Webview 요소는 themeable이어야 하고 접근성, ARIA label과 keyboard navigation을 따라야 한다.
- VS Code는 action을 toolbar 또는 view의 명시적 command surface에 두는 방식을 안내한다.
- React Card | Fluent 2 Design System
- Fluent 2는 card를 하나의 개념 또는 객체와 관련된 정보와 액션을 담는 컨테이너로 정의한다.
- 카드의 정보와 액션은 객체의 목적에 맞춰 선택할 수 있으므로 액션이 없는 단순 정보 카드도 개념적으로 일관된다.
- Master Your Workflow with Jira Kanban Boards
- Jira는 Kanban 카드가 각 work item의 가장 관련 있는 정보를 한눈에 전달해야 한다고 설명한다.
- Kanban 칼럼은 workflow 단계를 시각화하고 카드는 상태 흐름을 표현한다.
- Jira의 정보 밀도와 제품 기능을 VS Code Webview에 그대로 복제할 근거는 아니다.
- Pragmatic drag and drop accessibility guidelines
- Atlassian은 drag handle이 없는 draggable card에도 동등한 액션을 위한 More button이 있어야 한다고 안내한다.
- 타이틀만 보이면서 숨은 DnD만 유지하면 상호작용 affordance와 접근 가능한 대체 수단이 부족해진다.
- 후속 액션 재도입 시 실제 VS Code keyboard와 screen reader 검증이 별도로 필요하다.

### 3.4. request-and-goal

- Request and Goal

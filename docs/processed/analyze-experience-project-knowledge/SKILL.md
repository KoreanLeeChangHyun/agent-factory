# 경험 재사용과 프로젝트 지식 관리 개선안

- 작성일: 2026-09-10

- 상태: Hermes Agent 비교에서 도출한 설계 제안. 사용자가 요청한 범위는 MCP 저장소에 논의 내용을 기록하는 것이다. 기능 구현, API·스키마, 자동 실행 정책, 우선순위와 배포 일정은 확정하지 않는다.

<a id="소유권"></a>

## 1. 소유권

- 플러그인은 공개 스킬 `agent`와 `convention`만 유지한다. 경험·지식 관리 기능은 MCP 쪽 개선 대상으로 검토한다. MCP는 연결된 에이전트의 고유 기억·스킬·도구를 대체하거나 실행을 통제하는 별도 AI harness로 확장하지 않는다.

| 소유 | 책임 |
| --- | --- |
| MCP | 공유할 경험과 프로젝트 지식의 저장·검색·갱신, 출처·신선도·중복 관리, 프로필 자료와 결과 집계 제공 |
| 플러그인 `agent` | 작업 위임, 역할 경계, 제공된 근거를 작업에 적용하는 판단, 검증·완료 규칙 |
| 플러그인 `convention` | 프로젝트·개발 규칙, 문서 유형·권위, 소유권과 참조 원칙 |
| 연결된 에이전트 및 로컬 실행 런타임 | 실제 행동, 세션·실행·복구·그래프 전환과 실행 근거 생성 |

- 공유 지식의 저장소와 로컬 실행 기록을 구분한다. MCP가 받은 보고만으로 실제 실행이나 독립 검증의 완료를 단정하지 않는다. Git에 있는 스킬 원본의 작성·버전 관리는 기존 소유권을 유지하며, MCP 기록을 이유로 설치된 스킬을 자동 수정하지 않는다.

<a id="개선-후보"></a>

## 2. 개선 후보

<a id="작업-경험을-재사용-가능한-근거로-정리"></a>

### 2.1. 작업 경험을 재사용 가능한 근거로 정리

- 반복된 사용자 수정, 실패 조건, 시도한 접근, 확인된 해결 절차를 연결해 저장한다. 각 경험에는 프로젝트와 적용 범위, 원본 문서·run·결과 근거, 검증 여부를 연결한다. 검증을 생략한 결과는 검증된 해결책으로 기록하지 않는다.

- 경험에서 도출한 가설과 절차 후보는 비권위적 Processed 지식으로 다룬다. Specification 채택이나 스킬 변경은 별도 권위와 절차를 따른다. 이는 자동 승격 파이프라인이나 새로운 문서 유형을 만드는 제안이 아니다.

<a id="작업에-필요한-과거-경험-검색"></a>

### 2.2. 작업에 필요한 과거 경험 검색

- 현재 프로젝트·컴포넌트·작업 조건에 관련된 결정, 이전 실패, 해결 근거를 조회할 수 있도록 한다. 검색 결과에는 출처와 revision, 적용 조건, 최신성 판단 자료와 상충하는 근거를 제공한다. 검색 순위 자체가 문서의 권위나 현재 유효성을 의미하지 않는다.

- 기존 Document 검색·권한 경계를 우선 활용한다. 어떤 시점에 검색하고 결과를 실제 행동에 어떻게 반영할지는 에이전트의 책임으로 남긴다. MCP가 임의로 다음 실행을 시작하거나 도구·권한·작업 범위를 변경하지 않는다.

<a id="프로젝트-전문-프로필-자료-관리"></a>

### 2.3. 프로젝트 전문 프로필 자료 관리

- 아키텍처, 구성 요소, 적용 규칙, 채택된 결정과 관련 이력을 프로젝트별로 제공한다. 안정적인 규칙과 변경이 잦은 상태를 구분하고, 출처·버전·갱신 조건을 추적한다. 오래된 요약만으로 전문성이나 실행 권한이 생겼다고 간주하지 않는다.

- 프로필의 최소 표현, 충돌·무효화 정책, 기존 Agent 정의·버전과의 관계는 추가 설계가 필요하다. 세션 재사용과 실행 호환성 판단은 연결된 실행 주체의 계약과 분리한다.

<a id="유지관리와-효과-평가"></a>

### 2.4. 유지관리와 효과 평가

- 사용된 지식 revision·스킬 버전과 보고된 작업 결과를 연결해 반복 오류, 수정 횟수, 완료 시간과 토큰·비용의 변화를 비교할 수 있도록 한다. 보고되지 않은 값은 미상으로 남기며, 조회 횟수만으로 유용성이나 성공 원인을 단정하지 않는다.

- 중복·상충·오래된 지식은 정리 후보로 제시한다. 사용 빈도가 낮다는 이유만으로 권위 있는 규칙을 폐기하지 않는다. 비교 시 작업 유형·난이도·모델·검증 조건을 함께 기록해야 효과를 해석할 수 있다.

<a id="설계-시-확인할-항목"></a>

## 3. 설계 시 확인할 항목

- 기존 Document·검색·Agent reporting 모델로 표현 가능한 범위와 필요한 확장.
- 조직·Workspace·프로젝트별 조회 및 쓰기 권한, 공유 범위와 보존 정책.
- 경험 추출 주체, 수행 시점, 비용, 중복 처리와 사용자 수정 반영 방식.
- 갱신·상충 처리, 프로필 최소 표현과 원본 변경에 따른 무효화 기준.
- 스킬 변경 후보의 Git 작성 흐름과 MCP 지식 기록 사이의 참조 방식.
- 대표 작업의 재발 오류와 결과 개선을 평가할 기준 및 누락 데이터 처리.

- 첫 적용 후보는 경험 기록과 작업 시 조회를 연결하는 작은 사례다. 문서 수 증가보다 관련 근거가 다음 작업의 판단에 사용되고 반복 오류가 줄었는지를 관찰한다. 구현 순서와 채택 여부는 별도 결정한다.

- [Curator](https://hermes-agent.nousresearch.com/docs/user-guide/features/curator): 사용 이력, 오래된 스킬 관리와 복구.

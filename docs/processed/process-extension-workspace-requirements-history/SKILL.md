## 3. 본문 기록

### 3.1. acceptance-criteria

- acceptance-criteria
- Extension Development Host에서 workspace 명령으로 singleton Workspace Webview panel이 열리고 재호출 시 reveal된다.
- Dashboard, Editor, Kanban, Context 4개 탭이 동일 너비로 tablist 전체 폭을 채우고 선택 헤더 및 바디가 표시된다.
- 탭 선택, 키보드 탐색, 선택 상태 보존과 design 및 view 상태의 editor 이전이 검증된다.
- Dashboard와 Context는 기능 없는 shell이다.
- 본문 panel과 empty-state가 최대 폭 제한 및 바깥 좌우 여백 없이 에디터의 가용 폭을 채운다.
- 지원되는 VS Code 테마에서 탭, 헤더와 본문 표면이 semantic theme token으로 일관되게 표시된다.
- agents Extension Development Host에서 Agent Factory launcher View와 Agents 및 Workspace command links가 표시된다.
- file Explorer와 sidebar Agents Chat View가 표시되지 않는다.
- Agents command는 editor area에 singleton Agents Webview panel을 열고 재호출 시 같은 panel을 reveal한다.
- Workspace command는 editor area의 Workspace Webview panel을 연다.
- agents Chat이 Main과 Workflow 전환, 세션 생성과 선택 및 세션별 Composer 상태 보존을 지원한다.
- 메시지 전송은 Extension Host에서 포함된 Codex CLI의 codex exec --json 또는 resume를 실행하고 JSONL 이벤트를 해당 세션 DOM에 표시한다.
- 사용자는 실행 중 응답을 취소하고 panel 재연결 후 현재 세션 결과를 복원할 수 있다.
- linux-x64 VSIX 설치물에는 Codex CLI가 포함되고 ../web 파일이나 실행 중인 서버를 요구하지 않는다.
- Codex 인증이 없거나 실행이 실패하면 비밀을 노출하지 않는 오류와 복구 안내를 표시한다.
- Specification, 단위 테스트, 핵심 E2E 및 보안·테마·접근성·패키지 점검이 통과한다.
- 6개 canonical lifecycle 상태 열이 하나의 기본 Kanban 보드에 동시에 표시되고 상태 탭 또는 단일 선택 보드 UI가 존재하지 않는다.
- 칸반 표시 multi-picklist로 숨긴 상태 열 ID가 고정 localStorage key에 저장되고 다음 Webview 초기화에서 유효한 ID만 복원된다.
- localStorage 손상 데이터, 읽기 실패와 쓰기 실패가 Kanban 렌더링을 중단하지 않는다.
- Kanban 일반 notice DOM과 전이 요청, pending 및 성공 문구가 없고 snapshot 또는 manager 오류는 기존 오류 영역에 표시된다.
- Kanban 본문 좌우 padding과 열 사이 gap은 0이며 Webview 바깥 스크롤이 없고 각 카드 목록만 독립 세로 스크롤된다.
- 제목·id 검색, 필터 UI, 갱신 시각과 수동 새로 고침이 존재하지 않는다.
- 카드는 타이틀만 표시하고 id, metadata, select, button, draggable, click, tap, focus와 keyboard Move 상호작용이 없다.
- 관련 단위 테스트, workspace npm run check, git diff check와 Human 검토가 통과한다.
- Agents mode tabs, session header와 outer gutter가 Workspace 기준 hierarchy와 정합하게 표시된다.
- Composer는 Web 기준의 최소 72px card, transparent input과 우측 하단 28px action hierarchy를 사용하되 unsupported controls를 노출하지 않는다.
- 빈 input의 계산 높이는 20px이고 내용에 따라 최대 144px까지 자동 확장하며 native resize handle 없이 초과 내용을 내부 스크롤한다.
- 22px status line은 실행, 취소와 오류 상태를 표시하고 정상 완료 후 IDLE로 복귀한다.
- User message는 card로, Assistant message는 transparent text로 동일 turn 아래 렌더링된다.
- Enter, Shift+Enter, Ctrl 또는 Cmd+Enter와 IME composing negative path가 검증된다.
- submit, cancel, reconnect, draft restore, CSP, session DOM ownership과 Web runtime 독립성이 유지된다.
- 단위, 통합, VS Code Extension Host E2E 및 linux-x64 VSIX contents 검증이 통과한다.
- Editor 트리는 canonical Intake, Specification, Work Unit package와 선택 artifact의 section을 표시한다.
- 선택 artifact의 읽기 전용 JSON 미리보기는 textContent 기반이며 canonical 내용을 반영한다.
- 구조화 편집은 artifact manager의 allowlisted semantic operation으로 저장되고 성공 후 다시 읽힌다.
- 경로 이탈, symlink package, 미지원 artifact, 임의 manager 명령, malformed message와 stale documentVersion은 mutation 없이 거부된다.
- manager validation 실패는 authoritative package 상태를 보존하고 Human이 이해할 수 있는 오류를 표시한다.
- 기존 Kanban unit, manager integration과 Extension Host E2E가 통과한다.
- Agents와 Workspace의 상단 탭 및 선택 헤더가 저장된 Web 참조와 동일한 두 행 geometry를 사용한다.
- 두 확장의 대응 geometry가 서로 동일함을 source 및 단위 테스트로 검증한다.
- Human이 실행 화면에서 상단 탭 확대, 선택 헤더 축소와 양쪽 통일을 확인할 수 있다.

- 각 상태 열 헤더에는 개별 열기·닫기 컨트롤을 제공하지 않는다.
- Kanban 본문과 보드는 좌우 padding과 열 사이 gap 없이 가용 영역을 채우고 Webview 바깥 스크롤을 만들지 않으며 카드 목록만 독립적으로 세로 스크롤된다.
- Kanban 탭에서는 중복 선택 헤더와 수동 새로 고침 컨트롤을 표시하지 않는다.
- Kanban은 제목 또는 id 검색과 필터 UI 및 필터 상태를 제공하지 않는다.
- 카드는 타이틀만 표시한다.
- 카드는 정적 정보 항목이며 id, updatedAt, 실행·review·Human 승인·integration·PR 상태, Move 선택기, 버튼 또는 기타 액션을 표시하지 않는다.
- 카드는 draggable, click, tap, focus 또는 keyboard Move 상호작용을 제공하지 않는다.
- 보드는 상태별 항목 수, filesystem 변경 자동 갱신과 Webview 재연결 복원을 제공한다.
- Work Unit 상태 변경은 canonical manager 명령을 통해 수행한다.
- Work Unit 실행은 Goal, dedicated worktree와 execution state 계약을 통해 수행한다.
- Human review, rework, Git integration과 PR 생성은 Agent Factory lifecycle의 명시적 Human 결정으로 수행한다.
- Agents의 상단 mode tabs와 session header는 Workspace와 정합한 hierarchy 및 full-width outer surface를 제공한다.
- Agents composer는 하나의 bordered surface 안에 입력면과 우하단 send 또는 cancel action을 소유한다.
- Agents message history는 user와 assistant를 turn으로 묶고 role별 visual hierarchy를 구분한다.
- Enter는 메시지를 전송하고 Shift+Enter는 줄바꿈을 입력하며 Ctrl 또는 Cmd+Enter 전송도 호환한다.
- 세션별 draft, messages, loading, status, error 및 backend request ownership을 보존한다.
- Editor는 프로젝트의 canonical Intake, Specification, Work Unit package와 section을 탐색한다.
- Editor는 artifact와 section 트리, 구조화 semantic field 편집, 읽기 전용 JSON 미리보기를 제공한다.
- Extension Host는 공통 sectioned package 읽기와 artifact별 manager 쓰기 adapter를 분리한다.
- 편집 저장은 선택 artifact의 allowlisted manager semantic operation으로만 수행한다.
- 저장 직전 package identity, artifact type, documentVersion과 경로 안전성을 재검증한다.
- 저장 성공 또는 manager validation 실패 후 authoritative package 상태와 결과를 Webview에 반환한다.
- Agents와 Workspace는 상단 탭과 선택 헤더의 두 행 geometry를 동일하게 제공한다.
- 두 확장의 두 행 geometry는 저장된 Web 참조와 정합해야 한다.
- 이 geometry 변경은 탭 이름, 순서, DOM, 이벤트, 키보드와 상태 계약을 변경하지 않는다.
- Kanban은 지속적인 전이 요청, 검증 또는 성공 문구를 위한 일반 notice 영역을 표시하지 않는다.
- Kanban manager 또는 snapshot 오류는 기존 오류 영역에 표시한다.
- 칸반 표시 선택기의 닫힌 칼럼 ID 목록은 localStorage에 저장하고 Webview 초기화 시 유효한 칼럼 ID만 복원한다.
- localStorage 접근 또는 저장 실패는 Kanban 렌더링과 상태 전이를 중단하지 않는다.

### 3.7. quality-and-non-functional-requirements

- quality-and-non-functional-requirements
- VS Code 테마 토큰을 사용한다.
- 탭, 선택 헤더와 본문은 역할에 맞는 VS Code semantic theme token으로 일관된 표면 계층을 제공한다.
- 4개 탭은 동일 너비로 tablist 전체 폭을 채운다.
- 본문 panel과 empty-state는 최대 폭 제한 및 바깥 좌우 여백 없이 에디터의 가용 가로 폭을 사용한다.
- 키보드와 보조기술이 탭 구조와 선택 상태를 인식할 수 있어야 한다.
- Webview는 nonce 기반 CSP와 제한된 localResourceRoots를 사용한다.
- Webview는 파일시스템, Codex 실행 파일 또는 프로세스 명령에 직접 접근하지 않는다.
- Extension Host는 Webview 메시지를 허용 목록과 형식 검증 후 처리하고 Codex 프로세스 수명주기를 소유한다.
- launcher는 custom Webview나 command TreeItem 대신 native empty View와 viewsWelcome command links를 사용한다.
- 모든 사용자 아이콘은 실제 SVG를 사용한다.
- agents Chat의 UI 상태는 vscode.getState와 vscode.setState로 보존한다.
- Codex 인증 비밀은 Webview 메시지나 로그에 노출하지 않는다.
- Webview는 파일시스템, manager, Codex, Git 또는 GitHub 명령을 직접 실행하지 않는다.
- 지원하지 않는 schema, unsafe path, symlink와 snapshot 또는 manager failure는 mutation 없이 기존 오류 영역에 표시한다.
- Kanban 본문과 보드는 가용 영역을 채우고 카드 목록만 독립 세로 스크롤되며 시각적 스크롤바를 숨긴다.
- 숨긴 스크롤바와 무관하게 칸반 표시 선택기의 keyboard focus, 선택 상태와 accessible name 및 카드 목록의 wheel·trackpad scrolling을 유지한다.
- localStorage 읽기 또는 쓰기 실패와 손상 데이터는 Kanban 렌더링을 중단하지 않고 유효한 상태 열 ID만 상태에 반영한다.
- 정적인 Kanban 카드는 타이틀 외 정보나 숨은 interaction affordance를 포함하지 않는다.
- 강제 Git 작업, dirty worktree 제거, 자동 merge와 자동 PR promotion을 제공하지 않는다.
- Agents 채팅 UI는 VS Code semantic theme token을 사용하고 모든 icon-like control은 inline SVG로 렌더링한다.
- Webview는 Web source나 runtime을 import 또는 호출하지 않고 현재 Extension Host message allowlist를 유지한다.
- composer input은 빈 상태 20px에서 시작하고 내용에 따라 최대 144px까지 자동 확장한 뒤 내부 스크롤하며 native resize handle을 노출하지 않는다.
- composer card는 최소 72px와 12px 내부 여백을 유지하고 28px action을 우측 12px, 하단 12px에 정렬한다.
- status line은 22px 고정 높이이며 정상 완료 후 지속적인 완료 문구 대신 Web 기준 IDLE로 복귀한다.
- editor area의 좁은 editor group에서도 input과 action이 겹치지 않으며 keyboard focus와 accessible name을 유지한다.
- IME composing 중 Enter는 전송하지 않고 multiline 및 기존 submit shortcut 회귀를 방지한다.
- Editor Webview는 raw filesystem write, 임의 executable path, shell command 또는 임의 manager subcommand를 전달하지 않는다.
- Extension Host는 project root, package identity, artifact type, manager allowlist와 message allowlist를 소유한다.
- package path escape, symlink, unsupported schema 또는 artifact type과 stale documentVersion은 mutation 전에 거부한다.
- JSON 미리보기는 실행 가능한 markup이 아니라 textContent로 렌더링한다.
- manager 오류는 내부 명령 경로와 민감 정보를 노출하지 않는 구조화 오류로 표시한다.
- Editor 변경은 현재 Kanban rendering, visibility persistence와 오류 표시 계약을 변경하지 않는다.
- Agents와 Workspace의 탭 및 선택 헤더 geometry는 하나의 검증 기준으로 관리해 두 확장 사이 drift를 방지한다.
- Web 참조는 설계 근거이며 확장 런타임 또는 설치 의존성이 아니다.

## 3. 본문 기록

### 3.1. context-and-scope

- Context and Scope
- 내부 배포된 Agents 확장은 단순 textarea와 분리된 우측 action 열을 사용한다.
- Workspace 확장은 외부 gutter가 제거된 탭 및 선택 헤더 구조를 제공한다.
- Web 제품은 세션 소유 composer와 message list를 제공하지만 VS 확장 런타임과는 별도 제품이다.
- agents/src/chatView.js의 탭, 세션 헤더, composer, message list 및 keyboard submission 렌더링
- agents/test의 UI 구조, keyboard, 세션별 상태와 message contract 회귀 테스트
- 현재 linux-x64 VSIX 재패키징 및 설치 패키지 검증
- Web 소스 또는 Web 런타임 변경
- 이미지 첨부, 모델·reasoning 선택, Goal mode, 사용자 메시지 popover 등 현재 VS backend 계약에 없는 Web 전용 기능
- Windows, macOS, arm64 패키지
- 자동 배포, push, PR promotion과 Human 승인 없는 integration

### 3.2. decisions-and-open-items

- Decisions and Open Items
- Workspace의 tab 및 selected header hierarchy와 외부 gutter 제거 방식을 Agents에 적용한다.
- Web의 composer 및 message history visual hierarchy를 VS Webview에 독립 구현한다.
- Enter 전송, Shift+Enter 줄바꿈과 기존 Ctrl 또는 Cmd+Enter 전송을 함께 지원한다.
- 지원되지 않는 Web 전용 도구는 제외한다.
- 현재 session, backend, allowlist, CSP, SVG와 Web 독립 경계를 보존한다.
- Specification alignment 항목은 canonical Specification에 반영되었고 full validation을 통과했다.
- 실제 설치본 Human 시각 검토와 실제 인증 메시지 smoke는 구현 이후 남는다.
- integration, 재배포, cleanup, push와 PR promotion은 별도 Human 결정이다.
- 좁은 sidebar에서 action과 input이 겹칠 수 있으므로 responsive source 및 E2E 검증이 필요하다.
- Enter 동작 변경은 IME 조합 입력과 multiline 입력을 손상시킬 수 있으므로 negative path 테스트가 필요하다.
- 무관한 agent-factory-workspace-kanban-board Work Unit은 현재 untracked 상태이므로 staging 및 실행 범위에서 제외해야 한다.
- Human은 검증된 Agents 채팅 Web UI Specification 정렬 변경 7개 파일을 별도 커밋하는 선택지 A를 승인했다.
- 기존 agents VS Code 확장을 대상으로 제공 이미지 수준의 화면과 현재 지원되는 기능 범위만 구현한다.
- 기존 검증 불가 Work Unit을 보존하고 새 Work Unit을 생성한다.
- agent-factory-agents-chat-web-alignment-v2 Work Unit을 지금 실행한다.

### 3.3. evidence-and-findings

- Evidence and Findings
- Workspace는 상단 tablist와 별도 selected header를 사용한다.
- Workspace는 body, tablist와 panel 외부 gutter를 제거하고 읽기 콘텐츠 padding을 별도로 보존한다.
- Workspace 단위 테스트는 full-width outer surface와 내부 reading padding 경계를 고정한다.
- Agents 탭과 세션 헤더는 Workspace 구조를 직접 기준으로 삼을 수 있다.
- Workspace와 Agents의 기능은 달라 label, session state와 command contract는 공유하지 않는다.
- Web composer는 bordered card 안의 투명 contenteditable input과 하단 action 영역을 사용한다.
- 전송 action은 composer 우하단에 고정된다.
- Web message list는 user와 assistant를 turn으로 묶고 user는 카드, assistant는 무배경 전체 폭 텍스트로 렌더링한다.
- Web은 Enter 전송과 Shift+Enter 줄바꿈을 제공한다.
- 현재 VS backend가 지원하는 text submit, cancel, session state만 유지하면서 시각 hierarchy와 keyboard interaction을 독립 구현할 수 있다.
- Web 전용 이미지, 모델, Goal과 기타 도구는 현재 VS backend message contract로 지원되지 않는다.
- 현재 Agents는 상단 mode row와 session header row가 Workspace와 다른 높이 구조를 사용한다.
- 현재 composer는 textarea와 별도 우측 action 열을 사용하고 외부 padding을 가진다.
- 현재 user와 assistant 메시지는 모두 bordered bubble에 가깝고 turn wrapper가 없다.
- 현재 Ctrl 또는 Cmd+Enter만 submit한다.
- 기존 session id, draft state, submit/cancel allowlist와 CSP를 보존한 채 DOM hierarchy 및 CSS와 keyboard handler를 변경해야 한다.
- 실제 설치본의 Human 시각 검토는 구현 후 다시 필요하다.
- 좌우 여백과 탭·헤더를 Workspace 방식으로 정확히 맞출지 결정

- B

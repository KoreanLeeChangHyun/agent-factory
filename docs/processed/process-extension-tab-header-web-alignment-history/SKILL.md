## 3. 본문 기록

### 3.1. context-and-scope

- Context and Scope
- 현재 Agents와 Workspace는 서로 같은 탭 및 선택 헤더 높이를 사용한다.
- 현재 확장 높이는 Web의 확인된 두 행 geometry와 다르다.
- Human은 Web 기준 적용과 두 확장 통일을 확인했다.
- agents/src/chatView.js의 Web 대비 session header, message area, composer 및 status 표시 구조
- agents/src/chatBackend.js와 agents/src/codexAdapter.js의 현재 지원 세션 및 메시지 경계
- Agents 대응 단위, 통합 및 실제 렌더링 회귀 검증
- workspace/src 이하 Workspace 구현, 탭 구성, 기능 및 테스트 변경
- Web 소스와 Web backend 변경
- 현재 Agents가 지원하지 않는 Web 전용 기능을 근거 없이 추가하거나 가짜 control로 표시하는 변경

### 3.2. decisions-and-open-items

- Decisions and Open Items
- Web의 확인된 상단 탭 및 선택 헤더 geometry를 Agents와 Workspace 모두에 동일 적용한다.
- Human이 Web 기준을 확인한 뒤 양쪽 통일을 명시했다.
- accepted
- resolved
- VS Code host frame을 포함한 최종 설치 화면은 Human Review에서 확인한다.
- 기존 agent-factory-workspace-requirements Specification의 정합성 변경 4개 파일을 Intake checkpoint 전에 별도 커밋한다.
- Human이 A를 선택했다. Specification 생성은 필수가 아니지만 기존 관련 Specification의 accepted requirement 정렬은 필요하다.
- 현재 후속 Web 정합성 분석과 변경은 Agents 확장만 대상으로 한다.
- Human이 Workspace를 고려 대상에서 제외하고 Agents만 고려하라고 명시했다.
- Agents 전체 shell의 시각 구조를 현재 지원 기능 안에서 Web runtime evidence에 정합하고 Workspace는 변경하지 않는다.
- Human이 Agents만 고려하라는 범위 확정 후 실행을 지시했고, 기존 Specification이 동일한 Agents header, composer, message와 status 경계를 규정한다.

### 3.3. evidence-and-findings

- Evidence and Findings
- Agents mode tab과 Workspace tab은 동일한 현재 최소 높이를 사용한다.
- Agents session header와 Workspace selected header는 동일한 현재 최소 높이를 사용한다.
- 대응 단위 테스트가 Agents의 현재 두 높이를 직접 고정하며 Workspace 테스트는 tab 및 selected header 구조를 고정한다.
- 두 구현과 대응 테스트를 한 Work Unit에서 함께 변경해야 통일 상태를 검증할 수 있다.
- 실제 설치본 시각 검토는 구현 이후 Human Review에서 수행해야 한다.
- Web chat panel과 workspace panel은 동일한 상단 탭 행과 선택 헤더 행 geometry를 사용한다.
- Web의 상단 탭 행은 현재 확장보다 크고 선택 헤더 행은 현재 확장보다 작다.
- Human이 요청한 방향과 Web 기준 적용 결정이 일치한다.
- Web 소스는 참조 근거이며 VS Code 확장의 런타임 의존성으로 추가하지 않는다.
- 상단 탭과 선택 헤더 높이를 어느 기준으로 조정할지 결정
- A: Web 기준 geometry로 Agents와 Workspace 모두 통일
- B: 현재 확장에서 미세 조정
- C: 현재 높이 유지
- 확인된 Web source와 Human이 요청한 방향을 동시에 만족하며 두 확장의 geometry drift를 방지한다.
- A
- 검증된 기존 Specification 정합성 변경을 Work Unit 기준점 전에 커밋할지 결정
- A: 기존 Specification 변경 4개 파일만 커밋
- B: 커밋 없이 중단
- C: Specification 변경 철회
- 별도 Specification 생성은 필요하지 않지만 기존 canonical Specification이 해당 UI 요구사항을 소유하므로 accepted change를 정렬하고 실행 기준점에 포함해야 한다.
- Workspace selected header는 최소 높이를 32로 선언하지만 내부 Kanban board tab이 최소 높이 43을 요구한다.
- 내부 자식 높이 때문에 Workspace selected header의 실제 렌더링 높이는 Agents header와 동등한 32가 될 수 없다.
- 기존 회귀 테스트는 부모의 32 선언만 검사하고 자식의 43 충돌을 검사하지 않는다.
- Web 기준은 두 번째 행의 실제 높이를 32로 고정한다.
- Workspace Kanban board tab 높이와 회귀 테스트를 함께 수정해야 기존 Human 요구사항을 실제 렌더링에서 충족한다.
- 수정 설치 후 화면 반영에는 VS Code window reload가 필요할 수 있다.

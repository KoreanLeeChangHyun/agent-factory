# 워크스페이스 연결과 문서 저장 방식 논의 메모

- 기록일: 2026-09-05

- 사용자와의 대화에서 합의한 내용을 보존한 설계 메모입니다. 정식 명세나 구현 완료 기록이 아니며, 기존 코드·설정에 아직 반영되지 않은 결정이 포함되어 있습니다. 이 메모의 저장 경로는 제품의 문서 저장 경로를 정의하지 않습니다.

<a id="워크스페이스와-로컬-연결"></a>

## 1. 워크스페이스와 로컬 연결

- 우선 개인 사용자를 대상으로 설계합니다. 조직 워크스페이스는 이후에 다룹니다.
- 개인 사용자는 여러 워크스페이스를 소유할 수 있습니다.
- 로컬 프로젝트 디렉터리를 서버 워크스페이스에 연결합니다.
- 사용자는 로컬 VS Code에서 작업하고, AI는 MCP를 통해 연결된 워크스페이스를 사용합니다.
- 디렉터리 연결 자체가 로컬 파일의 업로드나 동기화를 의미하지는 않습니다.

<a id="문서의-성격과-저장-위치"></a>

## 2. 문서의 성격과 저장 위치

| 대상 | 성격 | 저장·접근 방식 |
|---|---|---|
| 원본 문서 | 외부에 존재하는 원자료 | 본문은 외부에 유지합니다. 클라우드에는 메타데이터·인덱스·링크만 저장합니다. MCP 검색기는 문서 정보와 링크를 찾고, 페치기(fetch)는 권한에 따라 외부 본문을 가져와 AI에 제공합니다. |
| 가공 문서 | 원본 조사, 웹 조사, 인터뷰 등으로 만든 정리·분석 문서 | 본문·출처·버전을 서버 워크스페이스에 저장하고 MCP로 검색·조회·수정합니다. |
| 명세 문서 | 정제된 지식 또는 사용자가 직접 정한 규칙·결정. 사람용 문서와 AI가 직접 사용할 스킬을 포함합니다. | 사람용 문서와 AI용 스킬 기준본은 서버에서 관리합니다. AI용 스킬은 연결된 로컬 프로젝트의 클라이언트용 스킬 디렉터리에 내려받아 사용합니다. |
| 임시 문서·작업 보조 파일 | 현재 작업에 필요한 중간 자료 | 로컬 프로젝트의 `.agent-factory/tmp/<작업-ID>/`에 저장하고 Git 추적에서 제외합니다. |

<a id="유형과-보존-상태"></a>

## 3. 유형과 보존 상태

- 원본·가공·명세는 역할에 따른 세 문서 유형입니다. 필수 처리 단계가 아닙니다.
- 가공 문서는 등록된 원본 문서 없이도 웹 조사나 인터뷰 등으로 만들 수 있습니다.
- 사용자의 직접적인 판단으로 규칙 등의 명세를 원본·가공 문서 없이 만들 수 있습니다.
- 실제로 참고하거나 파생한 관계가 있으면 출처와 관련 버전을 추적할 수 있게 남깁니다.
- 임시는 네 번째 문서 유형이 아니라 보존·관리 상태입니다.
- 완성도나 파일 확장자로 임시 자료와 가공 문서를 구분하지 않습니다.
- 처음부터 보존하고 재사용할 목적이라면 초안부터 서버의 가공 문서로 시작할 수 있습니다.
- 문서 작성에 사용한 일시적인 추출 결과, 계산용 파일 등의 보조 자료는 로컬 임시 경로에 둡니다.

<a id="기준본과-등록"></a>

## 4. 기준본과 등록

- 로컬 임시 자료를 가공 문서로 등록할 때 서버 저장 성공과 문서 ID 발급을 확인합니다.
- 등록 후에는 서버 문서가 기준본입니다. 로컬 파일이 남아 있어도 별도의 기준본으로 취급하지 않습니다.
- 명세의 사람용 문서와 AI용 스킬은 같은 내용을 유지해야 합니다.
- 워크스페이스 연결 시 스킬을 내려받고, 명세 변경 시 로컬 스킬을 갱신하는 기능이 필요합니다.

<a id="아직-정하지-않은-사항"></a>

## 5. 아직 정하지 않은 사항

- 디렉터리 연결 정보의 정확한 저장 경로와 형식
- AI 클라이언트별 로컬 스킬의 정확한 저장 경로
- 스킬 갱신 시점, 로컬 수정의 반영 방법과 충돌 처리
- 임시 자료의 삭제 시점과 정리 정책
- 여러 디렉터리와 워크스페이스 사이의 연결 개수 제약 및 복수 폴더 처리

<a id="구현과의-차이"></a>

## 6. 구현과의 차이

- 대화 중 확인한 기존 `.codex/skills/rule-platform/references/workspaces.md`와 관리 API는 조직 소속 워크스페이스를 전제로 합니다. 개인 소유 지원에는 별도 구현 변경이 필요합니다.
- 이 기록에서는 제품 코드, 런타임 저장 구조, 배포된 스킬 또는 정식 명세를 변경하지 않았습니다.

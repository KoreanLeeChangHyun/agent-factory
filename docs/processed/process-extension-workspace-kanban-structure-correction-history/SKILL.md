## 3. 본문 기록

### 3.1. context-and-scope

- Context and Scope
- workspace/src/webviewShell.js Kanban DOM, state, CSS와 DnD target
- workspace Kanban 단위 및 Extension Host 검증
- 관련 Specification 정합성 수정
- Kanban reader, controller와 manager 계약 변경
- canonical Work Unit lifecycle 상태 변경
- 다른 Workspace 탭과 Agents 변경
- Human 승인 전 재배포

### 3.2. decisions-and-open-items

- Decisions and Open Items
- 다중 열 칸반을 유지하고 갱신 시각 위치의 상단 컨트롤로 보드 전체를 열고 닫으며 열별 토글과 모든 좌우·열 사이 여백을 제거한다.
- 현재 수정 실행을 차단하는 열린 항목 없음

### 3.3. evidence-and-findings

- Evidence and Findings
- 배포 화면은 상태를 tablist와 tab으로 표시하고 선택 상태 하나만 본문에 표시한다.
- workspace-body overflow와 고정 viewport 높이 계산이 Webview 바깥 스크롤을 만든다.
- 수동 새로 고침 버튼은 Human 요청 없이 구현되었다.
- selected header가 활성 탭 이름 Kanban을 중복 표시한다.
- 단일 보드 변경 전 구현은 여러 칼럼을 표시했지만 1430px 최소 폭으로 좁은 화면에서 잘렸다.
- 이전 구현을 그대로 복원하지 않고 다중 칼럼 구조와 실제 viewport 경계를 함께 수정해야 한다.

### 3.4. request-and-goal

- Request and Goal
- 상태를 탭으로 만들지 않는다.
- 갱신 시각 정보는 표시하지 않는다.
- 갱신 시각이 있던 위치에서 칸반 전체를 열고 닫는다.
- 닫으면 6개 열을 포함한 칸반 보드 전체가 보이지 않는다.
- 각 칸반 열 헤더에 개별 열기·닫기를 만들지 않는다.
- 칸반 좌우 여백과 열 사이 여백을 모두 제거한다.
- Webview 바깥 스크롤이 생기면 안 된다.
- 6개 lifecycle 열이 상태 탭 없이 동시에 표시된다.
- 갱신 시각 정보가 없고 그 위치의 컨트롤로 칸반 보드 전체를 열고 닫는다.
- 닫힌 상태에서 칸반 보드 전체가 보이지 않고 상태가 복원된다.
- 각 열 헤더에 개별 열기·닫기 컨트롤이 없다.
- 칸반 좌우 여백과 열 사이 gap이 0이다.
- Webview 바깥 스크롤이 없다.

### 3.5. requirements-and-constraints

- Requirements and Constraints
- Kanban은 여러 lifecycle 열을 동시에 표시하는 기본 보드 구조를 사용한다.
- 상태 열을 tablist 또는 tab으로 구현하지 않는다.
- 갱신 시각을 제거하고 해당 상단 위치에 전체 Kanban 열기·닫기 컨트롤을 둔다.
- 전체 컨트롤을 닫으면 Kanban 보드 전체를 숨기고 상태를 복원한다.
- 각 열 헤더의 개별 열기·닫기를 제거한다.
- Kanban 좌우 padding과 열 사이 gap을 0으로 한다.
- 자동 watcher와 reconnect 갱신은 유지한다.
- canonical lifecycle와 transition capability 계약을 변경하지 않는다.
- 기존 미커밋 Agent Factory 산출물을 덮어쓰지 않는다.
- Webview 바깥 스크롤을 만들지 않는다.
- 890x950에서 여러 열, 전체 보드 열기·닫기, DnD와 카드가 동작한다.
- 갱신 시각, 상태 탭, selectedKanbanBoard, 수동 새로 고침, 중복 Kanban 제목과 열별 토글이 없다.
- Kanban 좌우 padding과 열 사이 gap이 0이고 Webview 바깥 스크롤이 없다.
- 단위, manager integration과 Extension Host E2E가 통과한다.

### 3.6. stakeholders-and-approval

- Stakeholders and Approval
- 실제 화면 검토와 승인 전 VSIX를 설치하지 않는다.
- 수정 범위를 넘어서는 UI 판단은 Human 확인을 받는다.

### 3.7. work-unit-basis

- Work Unit Basis
- gap-accepted-for-work-unit
- 상태 탭과 단일 선택 state 제거
- 다중 칼럼 및 열기·닫기
- 수동 새로 고침과 중복 제목 제거
- 바깥 스크롤 제거
